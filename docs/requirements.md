# Requirements and demonstration traceability

The [original DOCX](source/urumi-mcp-gateway-assignment.docx) is authoritative; [assignment.md](assignment.md) is its faithful reading copy. This document is a derived tracking view, not a replacement specification. Source labels below identify the assignment's actual headings: **Mandatory** means “Requirements (mandatory)”; **Stories** means “User stories”; **Done** means “Definition of done (must be testable)”; **Submission** means “Demo video and submission (mandatory)”.

Requirement IDs remain stable when plans change. Every planned implementation and verification method below is proposed unless recorded as accepted in [decisions.md](decisions.md). A verification plan is not evidence of passing it. “Not started” means no implementation/evidence; “Draft only” means incomplete documentation exists, not that the requirement is satisfied. Future status changes must link to the relevant change and test/demo evidence. No requirement is currently marked implemented or verified.

## Evaluation expectations and interpretation questions

The assignment gives two weeks but no start or submission date; no calendar deadline is inferred here. It values a working core over unfinished bonus work, encourages AI use while requiring personal understanding and defense of decisions, and explicitly grades the chat tool loop rather than model-answer quality. Round 2 includes an interview/live walkthrough; Round 3 is with founders. No scoring weights are supplied.

Unresolved interpretations are tracked as OPEN-01 through OPEN-07 in [architecture.md](architecture.md#unresolved-assignment-interpretations). They include upgrade/rollback scope, invitation mechanics, refresh behavior after disabling, audit attribution after revocation, failure-demo timing, client support for the cross-upstream prompt, and the meaning of “today” across timezones. None blocks faithful documentation; resolve each before the affected implementation or demo plan.
